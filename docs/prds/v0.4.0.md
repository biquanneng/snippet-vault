# SnippetVault v0.4.0 PRD：静默捕获 + 加密备份

状态：已实现（R1–R6），待浏览器验证与发布
更新时间：2026-10-19
来源：`docs/BACKLOG.md` 第 4 节与决策记录
当前版本：0.3.3

## 1. 背景

使用中暴露的问题：

1. `Cmd/Ctrl+C+C` 唤出的 Tooltip 在部分网站被页面元素盖住，点不到（F1）；
2. 侧边栏手动新建的记录没有来源，事后不知道它来自哪个网站（F2）；
3. Label 和 Context 依赖手动选择，保存时多一步，检索时帮助有限（F3）；
4. 备份是明文 JSON，多行内容满是转义字符，难以阅读，机密内容也没有保护（F4）。

v0.4.0 的目标是让捕获做到“零操作”，同时把备份做成可读又可加密的格式。多端同步
（F5）依赖合并导入，放在 v0.5.0。

## 2. 目标与非目标

目标：

- 网页选区快捷保存不需要任何点击；
- Content UI 在任何网站上都不会被页面元素遮挡；
- 自动给常见凭据格式打 Label，去掉 Context 这一层手动分类；
- 侧边栏新建自动带入当前页面来源；
- 备份改为 YAML，并默认加密。

非目标：

- 合并导入、多端同步（v0.5.0）；
- IndexedDB 内的本地加密与自动锁定（B15）；
- 凭据组等结构化记录（B10）；
- 新增任何远程请求或分析事件。

## 3. 需求

### 3.1 R1 Content UI 置于 Top Layer（B2）

**现状**：Content UI 是 WXT `position: "overlay"` 的 Shadow Root，内部容器使用
`fixed inset-0 z-99`（`entrypoints/content.tsx`）。宿主页面的高 `z-index` 元素、
原生 `<dialog>`、Popover 都可能盖住它。

**要求**：

- Content UI 根容器使用 Popover API（`popover="manual"`）进入浏览器 Top Layer，
  不再与宿主页面比较 `z-index`；
- 双击 `Shift` 打开 Modal、显示 Toast 时，重新调用 `showPopover()`，把容器移到
  Top Layer 最上方，压过宿主页面之后打开的 `<dialog>` 或 Popover；
- 重置 Popover 的 UA 默认样式（`inset`、`margin`、`border`、`padding`、
  `background`、`overflow`、尺寸），保持当前全屏透明、`pointer-events: none`
  的覆盖层行为；
- 浏览器不支持 Popover API 时回退到当前 `z-index` 方案；
- 不修改宿主页面的 DOM、样式或焦点，也不关闭宿主页面已经打开的 `<dialog>`。

**验收**：

- 在带有 `z-index: 2147483647` 浮层的页面上，Modal 和 Toast 可见并可点击；
- 宿主页面打开模态 `<dialog>` 后再双击 `Shift`，Modal 显示在最上层；
- 主题、语言切换和现有 Shadow DOM 样式边界不受影响。

**已知限制**：宿主页面的模态 `<dialog>` 打开时，浏览器会让 dialog 以外的内容
变为 inert，覆盖层可能可见但不可交互。实现时需要验证；如果无法绕过，在文档中
注明限制，不做修改宿主页面的 hack。

### 3.2 R2 下线 Context（B4）

**要求**：

- 删除以下界面中的 Context：选区捕获、检索面板新建和编辑表单、结果项、
  Context 筛选条、侧边栏设置“Context 与工作区”中的 Context 管理；
- 设置首页从四个分类调整为三个：**通用**、**Label**、**存储**。默认有效期天数
  移到“通用”；
- 结果项的“它属于哪里”由已有的来源行（页面标题或 Domain）承担；
- 搜索索引不再包含 Context 名称和颜色字段，中英环境别名随之移除。

**数据迁移（存储 schema v3 → v4）**：

1. 对每条带 `contextId` 的记录，取对应 Context 名称：内置环境 Context 使用迁移时
   界面语言下的名称，自定义 Context 使用保存的名称；
2. 按名称查找 Label（忽略大小写、去除首尾空格）：存在则复用，不存在则创建新的
   自定义 Label；Context 已归档时新 Label 同样归档，但仍保留在记录上；
3. 把该 Label 追加到记录 `labelIds` 末尾（已存在则不重复），然后移除 `contextId`；
4. 删除 `contextPresets` 存储，没有记录引用的 Context 直接丢弃；
5. 整个迁移在一个 IndexedDB 事务中完成。失败时保留 v3 数据，界面提示错误，
   不进入半迁移状态；
6. 迁移完成后重建搜索索引；
7. 迁移不改变记录的 `updatedAt`，避免影响后续并发冲突判断。

**验收**：

- 迁移后，用原 Context 名称检索能找到对应记录；
- 回归测试覆盖：同名 Label 复用、已归档 Context、无 Context 记录、无引用
  Context、事务失败回滚、重复执行迁移幂等；
- 消息契约中不再出现 Context 相关请求和字段。

### 3.3 R3 YAML 备份与加密（B6、B7）

**格式 v2**：

- 文件名 `snippet-vault-<UTC timestamp>.sv`，内容为 YAML；
- 导出时选择“加密（推荐，默认）”或“明文”；
- 明文备份示例：

```yaml
format: snippet-vault-export
formatVersion: 2
exportedAt: 2026-10-19T08:00:00.000Z
labels:
  - id: ak
    name: Access Key
    usageCount: 3
    createdAt: 2026-08-01T00:00:00.000Z
    updatedAt: 2026-08-01T00:00:00.000Z
items:
  - id: 01J...
    kind: vault
    labelIds: [ak]
    pinned: false
    source:
      title: RAM 访问控制
      url: https://ram.console.aliyun.com/users
      domain: ram.console.aliyun.com
    createdAt: 2026-10-01T00:00:00.000Z
    updatedAt: 2026-10-01T00:00:00.000Z
    content: |
      LTAI5t...
      第二行内容原样保留
```

- 加密备份示例，内层 `ciphertext` 解密后是与明文备份完全相同的 YAML：

```yaml
format: snippet-vault-export
formatVersion: 2
encryption:
  algorithm: AES-256-GCM
  kdf: PBKDF2-SHA-256
  iterations: 600000
  salt: <base64, 16 bytes>
  iv: <base64, 12 bytes>
ciphertext: <base64>
```

**序列化规则**：

- 字段顺序固定，`content` 放在每条记录最后；多行正文使用块标量 `|`；
- 时间统一为 ISO 8601 UTC 字符串；
- 不输出值为空的可选字段；
- 序列化后立即用解析器回读校验，沿用 v1“导出即校验”的约束。

**加密规则**：

- 全部使用 WebCrypto：PBKDF2-SHA-256 派生 AES-256-GCM 密钥，迭代 600,000 次，
  每次导出随机生成盐和 IV；
- 外层封套中除 `ciphertext` 以外的字段作为 AES-GCM 附加认证数据（AAD），
  篡改参数会导致解密失败；
- 口令至少 8 个字符，导出时需要输入两次确认；口令只在内存中临时使用，不保存；
- 界面明确说明：忘记口令无法恢复备份；
- 解密失败统一提示“口令错误或文件已损坏”，不区分具体原因。

**解析安全**：

- 引入 `yaml`（eemeli/yaml，ISC，无运行时依赖）；PR 中记录引入理由；
- 解析时只允许 core schema，禁止自定义 tag，限制别名展开数量，拒绝多文档流；
- 解析后的结构仍经过现有的字段长度、数量、引用完整性校验。

**兼容**：

- 导入时先识别格式：以 `{` 开头按 v1 JSON 解析，否则按 v2 YAML 解析；
- v1 中的 `contextPresets` 和 `contextId` 按 R2 迁移规则转为 Label；
- 导入仍是完整替换，预览、二次确认、预览后数据变化即拒绝等现有规则不变；
- 导出只生成 v2，不再生成 v1。

**验收**：

- 含多行 Markdown、引号、冒号、`#`、前导空格、Emoji 的内容能原样往返；
- 加密备份用正确口令能导入，用错误口令或篡改任意封套字段都会失败；
- v1 JSON 备份（含 Context）能导入并完成转换；
- 恶意 YAML（别名炸弹、自定义 tag、超长字段）被拒绝。

### 3.4 R4 自动识别格式并打 Label（B3）

**要求**：

- 新增纯本地的识别模块，输入正文，输出匹配到的内置 Label ID 列表；
- 只收录误报率低的规则：

| 规则 | 示例特征 | Label |
| --- | --- | --- |
| AWS Access Key ID | `AKIA` / `ASIA` + 16 位大写字母数字 | Access Key |
| 阿里云 AccessKey ID | `LTAI` + 12–30 位字母数字 | Access Key |
| GitHub Token | `ghp_`、`gho_`、`ghu_`、`ghs_`、`github_pat_` | Token |
| OpenAI / Anthropic Key | `sk-`、`sk-proj-`、`sk-ant-` 前缀 | API Key |
| JWT | 三段 base64url，以 `eyJ` 开头 | Token |
| PEM 私钥 | `-----BEGIN ... PRIVATE KEY-----` | Private Key |
| PEM 公钥 | `-----BEGIN PUBLIC KEY-----` | Public Key |
| 数据库连接串 | `postgres://`、`mysql://`、`mongodb(+srv)://`、`redis://` 且包含凭据 | Connection String（新增内置 Label） |

- 不识别无前缀的 40 位随机串（如 AWS Secret Key），避免误报；
- 多条规则同时命中时，按表格顺序去重输出；
- 应用场景：
  - R5 静默保存：直接写入识别结果；
  - 检索面板和侧边栏新建表单：正文变化时（防抖）把识别结果预选为 Label，
    用户可以取消；用户手动操作过 Label 后，不再自动覆盖；
- 编辑已有记录时不自动修改 Label。

**验收**：每条规则都有正例与反例单测，普通文本和代码片段不误报。

### 3.5 R5 快捷键静默保存（B1）

**要求**：

- 保留现有快捷键检测规则（400ms、同一选区、平台修饰键、可编辑控件排除等）；
- 第二次复制时不再显示 Tooltip，而是直接保存当前选区：
  - Markdown 转换、长度上限、来源记录沿用现有规则；
  - Label 由 R4 识别结果决定，可以为空；
  - 默认写入临时工作区，使用设置中的默认有效期；
- 保存成功后显示 Toast：“已保存到临时工作区 · N 天后过期”，提供**撤销**和
  **转为永久**两个操作，显示 6 秒；写入永久 Vault 时提示“已保存到 Vault”，只提供
  **撤销**；
- 撤销会删除刚保存的记录；转为永久沿用现有的转换接口和并发校验；
- 保存期间给选区一次短暂的扩展高亮闪烁作为视觉确认，不修改原生选区；
- 去重：当前目标中已存在正文完全相同的未过期记录时不新建，Toast 提示“已存在
  相同内容”；
- 设置“通用”新增“快捷保存位置：临时工作区 / Vault”，默认临时工作区，存在
  `local` storage 中，属于 UI 偏好，不进入备份；
- 原“选区提示例外”改名为“快捷保存例外”，规则数据和匹配逻辑不变，已有规则
  继续生效；Toast 中提供“在此页面停用 / 在此网站停用”入口；
- 删除 `SelectionTooltip` 及其只服务于 Tooltip 的代码；选区高亮能力保留。

**验收**：

- 选中文本后 `Cmd/Ctrl+C+C`，无需任何点击即完成保存，第一次复制的原生行为不变；
- 撤销后检索不到该记录；转为永久后出现在 Vault；
- 例外页面上快捷键不触发保存；
- Toast 在 R1 完成后不会被页面遮挡。

### 3.6 R6 侧边栏新建带入当前页面来源（B5）

**要求**：

- 侧边栏新建表单打开时，读取当前窗口活动标签页的标题和 URL，作为来源展示在
  表单顶部，带“移除来源”按钮；
- 只接受 `http:` / `https:` 页面；受限页面不带入来源；
- 表单打开期间用户切换标签页时，不自动替换已带入的来源；
- 保存时写入 `source.title`、`source.url`、`source.domain`，与网页选区保存一致；
- 页内双击 `Shift` Modal 的新建同样带入当前页面来源（无需新权限）；
- 编辑已有记录仍不允许修改来源。

**权限前提**：先验证 MV3 下 `<all_urls>` content script 匹配能否让侧边栏通过
`tabs.query` 读到 `tab.url`。

- 能读到：直接实现；
- 读不到：改为向活动标签页的 content script 发消息获取 `location.href` 和
  `document.title`，不新增 `tabs` 权限；content script 不可用的页面不带入来源。

**验收**：在普通网页打开侧边栏新建，来源自动带入；移除后保存的记录没有来源；
`chrome://` 页面不带入。

## 5. 实现顺序

| 步骤 | 需求 | 依赖 | 风险 |
| --- | --- | --- | --- |
| 1 | R1 Top Layer | 无 | 低；需要浏览器手动验证 |
| 2 | R2 下线 Context | 无 | 高；schema 迁移，约 20 个文件 |
| 3 | R3 YAML 加密备份 | R2 | 中；新增依赖、加密 |
| 4 | R4 自动 Label | R2 | 低 |
| 5 | R5 静默保存 | R1、R4 | 中；核心交互改变 |
| 6 | R6 侧边栏来源 | 无 | 低；需先验证权限 |

开发分支：`feature/v0.4.0`，从 `dev` 切出。每个步骤完成后可以单独提交；是否拆成
多个 PR 合入 `dev` 由维护者决定。

## 6. 验证

- 每个步骤运行 `pnpm compile` 和相关单元测试；
- R2、R3 属于高风险改动，运行 `pnpm test` 全量测试和 `pnpm build`；
- R1、R5、R6 需要在真实 Chrome 中手动验证，按全局规则先征得维护者同意，
  由维护者指定执行环境（例如 `pnpm test:browser -- --load-extension`）；
- 发布前将 `package.json` 版本更新为 `0.4.0`。

## 7. 风险

- **Context 迁移不可逆**：迁移后无法回到 v3。首次启动 v0.4.0 前，Release Notes
  需要提醒用户先导出备份；v0.3.x 导出的 v1 备份仍可在 v0.4.0 导入；
- **v0.3.x 无法导入 v2 备份**：需要在 Release Notes 中说明；
- **宿主页面模态 dialog 下的 inert 限制**：见 R1；
- **静默保存误存**：通过默认写入临时工作区、撤销和去重来降低成本；
- **识别规则误报**：只收录带明确前缀的格式，并允许用户在表单中取消预选。
