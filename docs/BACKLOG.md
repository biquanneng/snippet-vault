# SnippetVault 需求积压

状态：需求梳理草案
更新时间：2026-10-19

本文件记录尚未进入实现的需求、使用反馈和候选版本范围。需求一旦确定进入某个
版本并改变产品行为，必须同步更新 `docs/PRODUCT.md`；本文件只负责积压与排期。

## 1. 产品方向

差异化定位：

> 在哪里看到，就在哪里存下；在哪里需要，就在哪里用上；用完自动消失。

SnippetVault 专注于开发凭据与工作片段从产生、使用到过期的整个过程，不与密码管理器
比登录填充，也不与笔记工具比长文档管理。

明确不做：

- 登录表单自动填充；
- 长笔记、文件夹树、富文本编辑；
- 接入 AI 服务或任何会让片段离开本地的分析；
- SnippetVault 自有账号体系和托管云。

## 2. 用户使用反馈

| 编号 | 反馈 | 现状与原因 | 关联需求 |
| --- | --- | --- | --- |
| F1 | `Ctrl/Cmd+C+C` 唤出的 Tooltip 因层级问题点不到，希望改为快捷键直接静默保存 | Content UI 是 `position: overlay` 的 Shadow Root，容器使用 `z-99`（`entrypoints/content.tsx`）。宿主页面的高 `z-index` 元素、原生 `<dialog>` / Popover 顶层元素会盖住它；双击 `Shift` 的 Modal 也有同样风险 | B1、B2 |
| F2 | 侧边栏新建时希望带入当前标签页的网站和 URL | 手动新建按设计不写入来源（`PRODUCT.md` 5.2），侧边栏也没有读取当前标签页 | B5 |
| F3 | Label 和 Context 比较鸡肋，没有实质帮助 | 两者都依赖手动选择，保存时增加操作，检索时又不比全文搜索更有用 | B3、B4 |
| F4 | 导出文件是 JSON 不合适，希望 YAML 或其他格式，并引入加密 | 当前导出 `.sv` 版本化明文 JSON（`lib/backup-format.ts`），文件内机密可直接阅读 | B6、B7 |
| F5 | 备份还原希望支持多端同步 | 当前导入只做完整替换，不合并；删除没有墓碑记录，无法区分“对端删除”与“本端新增” | B8、B9 |

## 3. 需求池

优先级：P0 下个版本必须做；P1 下个版本尽量做；P2 后续版本；P3 远期。

### 3.1 捕获

**B1 快捷键静默保存（P0，来源 F1）**

- 网页选区上 `Cmd/Ctrl+C+C` 直接保存，不再弹出需要点击的 Tooltip；
- 保存后用 Toast 反馈，Toast 提供“撤销”和“转为永久 / 补充信息”操作；
- 来源标题、URL、Domain 自动记录；
- 已决策：默认写入临时工作区（自动过期、误存成本低），使用默认有效期；设置
  “通用”中可改为默认写入永久 Vault；
- 原 Tooltip 的“在此页面 / 网站不显示”例外改为“在此页面 / 网站停用快捷保存”，
  已保存的例外规则继续生效。

**B2 Content UI 置顶层（P0，来源 F1）**

- 双击 `Shift` Modal 和 Toast 改为使用浏览器 Top Layer（Popover API 或
  `<dialog>`），不再与宿主页面比 `z-index`；
- 即使 B1 去掉了 Tooltip，Modal 和 Toast 仍需要可点击，所以根因必须修。

**B3 格式识别与自动 Label（P0，来源 F3 与方向建议）**

- 本地正则识别常见格式：AWS `AKIA...`、阿里云 `LTAI...`、JWT、GitHub
  `ghp_` / `github_pat_`、OpenAI `sk-...`、数据库连接串、PEM 私钥、URL / Endpoint；
- 识别结果自动作为 Label 写入，用户不需要手动选择；
- 识别完全在本地完成，不发送任何内容。

**B4 下线 Context，简化 Label（P0，来源 F3）**

- 已决策：Context 整体下线，包括捕获、新建、编辑、结果展示、筛选、设置页
  “Context 与工作区”中的 Context 管理和颜色预设；默认有效期设置移到“通用”；
- 来源 Domain 作为隐式上下文，承担原来 Context 的“它属于哪里”；
- 保存流程不再要求选择 Label；Label 由 B3 自动生成，用户仍可在编辑时手动修改，
  设置页 Label 管理保留；
- 数据迁移（存储 schema v3 → v4）：每条记录关联的 Context 名称转换为同名 Label
  追加到该记录（同名 Label 复用，不重复创建），随后移除 `contextId` 和 Context
  预设。这样历史上下文仍可检索，不丢失语义；
- 迁移前提示用户先导出备份；迁移需要回归测试覆盖：同名复用、已归档 Context、
  无 Context 记录、迁移失败保持旧数据；
- 导入旧版 v1 备份时按同样规则把 Context 转为 Label；
- 影响范围：`lib/core`（model、repository、indexeddb-repository、search-index、
  vault-service）、`lib/browser` 消息契约与控制器、`lib/backup-format.ts`、
  `lib/context-colors.ts`、`components/context-marker.tsx`、检索面板、表单、
  Tooltip 和设置页，约 20 个源文件。

**B10 凭据组（P2）**

- 云控制台常一次给出 AK + SK + Region，支持作为一条结构化记录整体保存；
- 需要调整数据模型和表单，改动面大，放到后续版本。

### 3.2 取用

**B5 侧边栏新建带入当前标签页来源（P0，来源 F2）**

- 侧边栏新建表单默认带入当前活动标签页的标题、URL 和 Domain，并展示出来，
  用户可以一键移除；
- 受限页面（`chrome://`、Web Store 等）不带入来源；
- 需验证：读取 `tab.url` 是否需要额外申请 `tabs` 权限。现有 content script
  的全站匹配可能已经覆盖，如果需要新增权限，要先评估安装提示的变化。

**B11 当前站点优先（P1）**

- 双击 `Shift` 或侧边栏在检索词为空时，优先展示当前站点 Domain 的记录。

**B12 按格式复制（P1）**

- 复制为 `export KEY=...`、`.env` 行、JSON 字段、HTTP Header。

**B13 默认遮罩显示（P1，已搁置）**

- 被识别为机密格式的内容默认打码，悬停或按快捷键再显示明文，避免截图和屏幕
  共享时泄露。
- 已搁置：检索结果直接展示已保存内容，见决策记录 2026-10-27。

**B14 首次使用引导（P1）**

- 首次安装后在侧边栏展示 `Cmd/Ctrl+C+C` 和双击 `Shift` 的简短演示。

### 3.3 备份、加密与同步

**B6 加密备份（P0，来源 F4）**

- 导出默认加密：口令经 PBKDF2-SHA-256 派生密钥，使用 AES-GCM 加密，全部依赖
  WebCrypto，不新增依赖；
- 文件结构为带版本号的外层封套（算法、盐、迭代次数、IV）加密文；
- 口令只在导出、导入时临时使用，不保存；忘记口令则无法恢复，界面必须明确说明；
- 保留可选的“导出明文”，并保持现有风险提示。

**B7 备份格式改为 YAML（P0，来源 F4）**

- 已决策：备份格式 v2 使用 YAML。JSON 中大量转义的 `\n`、引号和括号对开发者
  不友好；YAML 的块标量 `|` 可以原样保留多行正文和 Markdown；
- 明文备份是可直接阅读的 YAML；加密备份的外层封套同样是 YAML（格式、版本、
  KDF 参数、盐、IV），内层被加密的明文也是 YAML，解密后可读性一致；
- 文件扩展名保持 `.sv`，导入时按内容识别 v1 JSON 与 v2 YAML，v1 继续可导入；
- 新增依赖：`yaml`（eemeli/yaml，ISC，无运行时依赖），用于安全解析，禁止
  自定义 tag 和别名展开，避免 billion laughs 一类问题；按仓库规则在 PR 中
  说明理由；
- 时间字段使用 ISO 8601 字符串，字段顺序固定，便于人工 diff。

**B8 合并导入（P2，来源 F5，不进入 v0.4.0）**

- 导入支持“合并”模式：按稳定 ID 合并，`updatedAt` 较新者胜；
- 引入删除墓碑（tombstone），记录被删除的 ID 和时间，防止已删除记录被对端复活；
- 涉及存储 schema 迁移，需要补回归测试。

**B9 多端同步（P2，来源 F5）**

- 基于 B6 加密与 B8 合并，同步到用户自己的存储：WebDAV、Cloudflare R2、S3
  兼容存储；
- 数据只经过用户自己的存储，不经过 biqn.dev；
- `chrome.storage.sync` 单项和总量上限太小，不作为方案；
- 凭据保存、传输、冲突和回滚需要单独安全评审（`PRODUCT.md` 6.3 已要求）。

### 3.4 信任

- 需要同时解决搜索索引加密或解锁后重建的问题，改动面大。

**B16 最小权限模式（P3）**

**B17 可复现构建（P3）**

## 4. 候选版本：v0.4.0「静默捕获 + 加密备份」

目标：解决 F1–F4，并为 F5 的多端同步打基础。

| 需求 | 优先级 | 说明 |
| --- | --- | --- |
| B1 静默保存 | P0 | 核心交互改变，默认写入临时工作区 |
| B2 Top Layer | P0 | 修复层级根因 |
| B3 自动 Label | P0 | 替代手动标注 |
| B4 下线 Context | P0 | 改动面最大，含 schema v4 迁移 |
| B5 侧边栏新建带来源 | P0 | 需要先验证权限 |
| B6 加密备份 | P0 | 与 B7 一起实现 |
| B7 YAML 备份格式 | P0 | 新增 `yaml` 依赖，兼容导入 v1 JSON |

建议实现顺序（每步一个独立 PR，并在同一 PR 中更新 `PRODUCT.md` 对应章节）：

1. B2 Top Layer：独立、风险低，先解决“点不到”；
2. B4 下线 Context：先做数据迁移和数据层，再清理 UI；后续需求都在更简单的模型上做；
3. B7 + B6 YAML 加密备份：依赖 B4 之后的数据模型；
4. B3 自动 Label，然后 B1 静默保存：B1 依赖 B3 才有意义；
5. B5 侧边栏新建带来源。

v0.5.0 候选：B8 合并导入、B9 多端同步、B11 当前站点优先、B12 按格式复制、
B13 默认遮罩、B14 首次使用引导。
