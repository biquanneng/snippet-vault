# SnippetVault 0.4.0

## Highlights

- **Quick save without a form.** Select content and press `Command/Ctrl+C`
  twice to save it instantly. No tooltip, no labels to pick.
- **Labels detected for you.** Common credential formats are recognized
  locally and labeled automatically.
- **Encrypted, readable backups.** Backups are now YAML and encrypted with a
  passphrase by default.
- **Sources for manual snippets.** New snippets remember the web page you were
  on.

## Changes

- `Command/Ctrl+C+C` saves the selection silently. The first copy is still a
  normal browser copy. A confirmation offers **Undo**, **Move to vault** for
  temporary records, and **More** to turn quick save off on the current page or
  site.
- Quick save goes to the temporary workspace by default. Choose the Vault under
  **Settings → General → Quick save**. Saving identical content to the same
  place again reuses the existing record.
- Labels are detected locally for AWS and Alibaba Cloud access key IDs, GitHub
  tokens, JWTs, `sk-` API keys, PEM and SSH keys, and database connection
  strings that include credentials. Unprefixed random strings are not
  detected. In the **New** form, choosing labels yourself overrides detection.
- New built-in label: **Connection String**.
- Contexts have been removed from capture, forms, results, filters, and
  settings. The source page title and domain now answer "where does this
  belong".
- Settings are reorganized into **General**, **Labels**, and **Storage**. The
  default temporary expiry moved to **General**.
- **New** in the side panel and in-page search captures the current page title
  and URL as the source. You can remove it before saving. No new permission is
  requested.
- Backups (`.sv`) are YAML, format version 2. Multi-line content is kept
  verbatim and placed last in each record, so files are easy to read and diff.
- In-page UI renders in the browser's top layer, so page overlays no longer
  cover it.

## Migration and compatibility

- **Export a backup before upgrading.** The first start of 0.4.0 converts every
  record's context into a label in one atomic storage migration (schema v3 → v4).
  The migration cannot be reversed.
  - The four environment contexts become built-in labels that follow the UI
    language.
  - Custom contexts reuse a label with the same name (ignoring case and
    surrounding spaces) or become a new label. Archived contexts become
    archived labels that stay on their records.
  - Record update times are not changed. If the migration fails, the previous
    data is kept.
- SnippetVault 0.3.x cannot read version 2 backups.
- Version 1 JSON backups still import. Their contexts are converted to labels
  with the same rules.
- Older backups without the **Connection String** label still import; the label
  is added automatically.
- Existing "selection tooltip exceptions" keep working as quick save
  exceptions.

## Security notes

- Encrypted backups use PBKDF2-SHA-256 with 600,000 iterations and a random
  salt, and AES-256-GCM with a random IV, all through WebCrypto. Every
  parameter in the file is authenticated, so tampering makes decryption fail.
- Encryption and decryption run only in the side panel. The passphrase is never
  stored or sent to the background.
- **A forgotten passphrase cannot be recovered.** A wrong passphrase and a
  damaged file show the same error.
- Plaintext export is still available and contains everything in readable form.
- The live IndexedDB database is still stored as plaintext in the browser
  profile.

## Known limitations

- When a page has its own modal dialog open, the browser may show SnippetVault
  UI without letting you interact with it.
- Quick save works only in the page's top frame. Content inside iframes cannot
  be quick-saved.

# SnippetVault 0.4.0（简体中文）

## 亮点

- **快捷保存，无需填写。** 选中内容后按两次 `Command/Ctrl+C` 即可保存，不再弹出
  提示框，也不需要选择标签。
- **自动识别标签。** 在本地识别常见凭据格式并自动打上标签。
- **可读且加密的备份。** 备份改为 YAML，默认使用口令加密。
- **手动新建也有来源。** 新建片段会记录你当时所在的网页。

## 变更

- `Command/Ctrl+C+C` 静默保存选区，第一次复制仍是浏览器的正常复制。保存后的提示
  提供“撤销”、“转为保管库”（仅临时记录），以及“更多”：可在当前页面或网站停用
  快捷保存。
- 快捷保存默认写入临时工作区，可在“设置 → 通用 → 快捷保存”改为保管库。相同内容
  再次保存到同一位置时复用已有记录。
- 本地识别以下格式并自动打标签：AWS 和阿里云 AccessKey ID、GitHub Token、JWT、
  `sk-` 开头的 API Key、PEM 与 SSH 密钥、带账号密码的数据库连接串。不识别没有前缀
  的随机串。在“新建”表单中手动选择标签后，以手动选择为准。
- 新增内置标签 **Connection String**。
- Context 已从捕获、表单、结果、筛选和设置中移除，“它属于哪里”改由来源页面的标题
  和域名回答。
- 设置调整为“通用”、“标签”、“存储”三类，默认有效期移到“通用”。
- 在侧边栏和页内检索中“新建”时，会带入当前网页的标题和 URL 作为来源，保存前可以
  移除。不申请新的权限。
- 备份（`.sv`）改为 YAML 格式版本 2。多行正文原样保存并放在每条记录末尾，便于阅读
  和比对。
- 页内界面改为显示在浏览器顶层（Top Layer），不再被网页浮层遮挡。

## 迁移与兼容

- **升级前请先导出备份。** 0.4.0 首次启动时，会在一次原子的存储迁移中（schema
  v3 → v4）把每条记录的 Context 转为标签，迁移不可回退。
  - 开发、测试、预发布、生产四个环境 Context 转为跟随界面语言显示的内置标签。
  - 自定义 Context 复用同名标签（忽略大小写和首尾空格），没有同名标签时新建。已归档的
    Context 转为已归档标签，并继续保留在原记录上。
  - 迁移不改变记录的更新时间；迁移失败时保留原数据。
- SnippetVault 0.3.x 无法读取格式版本 2 的备份。
- 旧版 v1 JSON 备份仍可导入，其中的 Context 按同样规则转为标签。
- 缺少 **Connection String** 标签的旧备份仍可导入，导入时自动补齐。
- 原有的“选区提示例外”继续作为快捷保存例外生效。

## 安全说明

- 加密备份使用 PBKDF2-SHA-256（600,000 次迭代、随机盐）和 AES-256-GCM（随机
  IV），全部通过 WebCrypto 实现。文件中的所有参数都参与认证，篡改会导致解密失败。
- 加密与解密只在侧边栏中进行，口令不会被保存，也不会发送到后台。
- **忘记口令将无法恢复备份。** 口令错误和文件损坏显示相同的提示。
- 仍可选择明文导出，明文文件中的所有内容均可直接读取。
- 扩展内的 IndexedDB 数据库仍以明文保存在浏览器 Profile 中。

## 已知限制

- 网页自身打开模态对话框时，浏览器可能让 SnippetVault 界面可见但无法交互。
- 快捷保存只在页面顶层 frame 中可用，iframe 中的内容无法快捷保存。
